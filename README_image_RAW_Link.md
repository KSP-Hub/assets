# ❌ Запрос

## 1. 🔴Описание проблемы

Файлообменники (Mail.ru, Yandex Disk и т.п.) не выдают прямые ссылки с явным расширением файла (.jpg, .png и т.п.) — это принципиальная особенность их сервиса. По соображениям безопасности.

    Сервисы генерирует короткие уникальные ссылки вида. Например: https://cloud.mail.ru/public/XXXX/YYYYY — без указания расширения. Это сделано:

* для безопасности (скрытие реального пути и типа файла);
* для удобства (короткие URL);
* для управления доступом (ссылки могут быть временными или требовать авторизации).



# 🟢 Решение 1

К сожалению, **напрямую получить ссылку с расширением `.jpg` (или другим) из Яндекс Диска невозможно** — сервис специально скрывает реальные пути к файлам и выдаёт короткие ссылки вида `https://disk.yandex.ru/i/...`.

Но есть **рабочие способы** решить задачу.

### Способ 1. Скачать и загрузить куда‑то ещё (рекомендуется)

1. Откройте изображение на Яндекс Диске.

2. Нажмите **«Скачать»** — файл сохранится на ваш компьютер с правильным расширением (`.jpg`, `.png` и т. п.).

3. Загрузите этот файл на другой хостинг/сервис, который даёт прямые ссылки с расширением:
   
   * GitHub (в репозиторий, потом берите `raw`‑ссылку);
   
   * Cloudinary, Imgur, Postimages и т. п.;
   
   * ваш собственный сервер/сайт.

**Плюсы:**

* получаете стабильную ссылку с нужным расширением;

* контроль над файлом и сроком жизни ссылки.

**Минусы:**

* нужно дополнительное хранилище.

* * *

### Способ 2. Использовать API Яндекс Диска (сложно, для разработчиков)

Через Яндекс Диск API можно получить прямой URL для скачивания, но:

* нужна регистрация приложения в Яндекс OAuth;

* требуется программирование (HTTP‑запросы, обработка токенов);

* ссылка временная (обычно несколько часов).

**Не подходит** для простой вставки в HTML.

* * *

### Способ 3. Попробовать «сырой» URL (не всегда работает)

Иногда помогает замена `/i/` на `/public/` и добавление `?dl=1`:
    https://disk.yandex.ru/public/sleeKZidn9wggw?dl=1

Но:

* ⛔ не гарантирует расширение `.jpg` в конце;

* может отдавать файл без MIME‑типа;

* ⛔Яндекс может блокировать такой доступ.



## 2. 🔴Описание проблемы

Как в GitHub сделать рабочую и стабильную ссылку? Я отрыл фотографию .webp из репозитария.

Например. Сделал copy permalink: https://github.com/KSP-Hub/assets/blob/2037e976906bfcd10c14d32c2c3f9deef4f734fd/karamin-stanislav-image.webp  
Но эти ссылка работает, потом не работают.



# 🟢 Решение 2

Чтобы получить **стабильную raw‑ссылку** на изображение в GitHub, нужно правильно сформировать URL. Проблема ваших текущих ссылок в том, что они ведут на страницу просмотра файла (`blob`), а не на сам файл.

Как получить правильную raw‑ссылку

----------------------------------

### Способ 1. Через интерфейс GitHub (простой)

1. Откройте файл изображения в репозитории.

2. Нажмите кнопку **`Download`** (она есть над содержимым файла).

3. В адресной строке браузера появится ссылка с доменом `raw.githubusercontent.com` — это и есть нужная raw‑ссылка.

4. Скопируйте её.

### Способ 2. Вручную исправить URL

Замените в вашей ссылке:

* `github.com` → `raw.githubusercontent.com`

* `/blob/` → `/`

**Пример:**

Исходная ссылка:  
`https://github.com/KSP-Hub/assets/blob/2037e976906bfcd1 Newton/c14d32c2c3f9deef4f734fd/karamin-stanislav-image.webp`

Исправленная raw‑ссылка:  
`https://raw.githubusercontent.com/KSP-Hub/assets/2037e976906bfcd10c14d32c2c3f9deef4f734fd/karamin-stanislav-image.webp`

### Способ 3. Через контекстное меню (быстрый)

1. На странице файла нажмите правой кнопкой мыши на изображение.

2. Выберите **«Открыть изображение в новой вкладке»** (или аналог в вашем браузере).

3. В новой вкладке будет правильная raw‑ссылка — скопируйте её из адресной строки.

Почему ссылки «работают, потом не работают»
-------------------------------------------

Ваши текущие ссылки нестабильны по двум причинам:

1. **Они ведут на HTML‑страницу**, а не на файл. Браузер показывает изображение _внутри_ страницы GitHub, а не загружает его напрямую.

2. **Используют хэш коммита** (`2037e97...`). Если вы обновите файл, хэш изменится, и старая ссылка перестанет работать.

Как сделать ссылку максимально стабильной
-----------------------------------------

Чтобы ссылка не ломалась при обновлении файла:

1. Используйте ветку вместо хэша коммита. Например, вместо:  
   `.../2037e976906bfcd10c14d32c2c3f9deef4f734fd/karamin-stanislav-image.webp`  
   пишите:  
   `.../main/karamin-stanislav-image.webp`  
   (если ваша основная ветка называется `main`).

2. Итоговая стабильная ссылка будет выглядеть так:  
   `https://raw.githubusercontent.com/KSP-Hub/assets/main/karamin-stanislav-image.webp`

Важные замечания
----------------

* **Домен:** всегда `raw.githubusercontent.com` (не `github.com`).

* **Без `/blob/`:** в raw‑ссылке не должно быть этого сегмента.

* **Проверка:** вставьте ссылку в адресную строку браузера — если изображение отображается сразу (без интерфейса GitHub), значит, всё верно.

* **Ограничения:** GitHub может временно блокировать очень частые запросы к raw‑файлам (защита от перегрузок).

Пример использования в HTML
---------------------------

```html
<img src="https://raw.githubusercontent.com/KSP-Hub/assets/main/karamin-stanislav-image.webp" alt="Моё фото">
```
